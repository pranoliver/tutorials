C Language: From Zero to Systems Programming

Chapter 1

Introduction + Installation

C is a small, fast, portable systems programming language. It powers operating systems, embedded firmware, databases, language runtimes, and any software where raw performance matters. Learning C gives you a mental model of how computers actually work.

Why learn C?

  • Systems: Linux, Windows kernels, and device drivers are written in C.
  • Embedded: Microcontrollers and IoT devices run C with tiny memory footprints.
  • Databases: PostgreSQL, SQLite, Redis, and many engines are built in C.
  • Performance: Predictable memory layout, no runtime overhead, direct hardware access.
  • Foundation: C is the common ancestor of C++, Objective-C, and many scripting language interpreters.

Before you start

  • A text editor and a terminal (new to the command line? Try the Linux tutorial).
  • Optional: Git basics for saving your projects.
  • No prior programming experience required, but patience helps.

What the compiler does

Building a C program is a pipeline of four stages:

  1. Preprocessor handles #include, #define, and conditional compilation.
  2. Compiler turns preprocessed C into assembly.
  3. Assembler turns assembly into an object file (.o).
  4. Linker joins object files and libraries into an executable.

Chapter 2

Program Structure & Compilation Model

A C program is a collection of declarations, statements, and comments. Understanding how the compiler processes your source helps you read error messages and control the build. 

/* tokens.c */
#include <stdio.h>

int main(void) {          /* function definition */
    int count = 10;       /* declaration + statement */
    count = count + 1;    /* expression statement */

    if (count > 0) {      /* compound statement / block */
        printf("Count is %d\n", count);
    }

    return 0;             /* return statement */
}

Core building blocks

  • Tokens: identifiers, keywords, literals, operators, and separators.
  • Statements: actions ending with a semicolon.
  • Blocks: statements grouped by {}.
  • Functions: named blocks that receive arguments and may return a value.
  • Comments: /* block */ or // line (C99+).

main and return values

Every hosted program starts in main. Return 0 for success and a non-zero value for failure. The operating system can read this exit code.

Preprocessor directives

#include <stdio.h>     /* system header */
#include "mylib.h"     /* project header */

#define PI 3.14159     /* constant macro */
#define SQUARE(x) ((x) * (x))  /* function-like macro */

#ifdef DEBUG
    #define LOG(fmt, ...) fprintf(stderr, fmt, __VA_ARGS__)
#else
    #define LOG(fmt, ...) ((void)0)
#endif

Compilation stages with GCC

gcc -E hello.c -o hello.i     # Preprocess only
gcc -S hello.i -o hello.s     # Compile to assembly
gcc -c hello.s -o hello.o     # Assemble to object
gcc hello.o -o hello          # Link executable

# All at once
gcc -std=c11 -Wall -Wextra -O2 hello.c -o hello

Chapter 3

Variables, Data Types, Operators

C exposes the machine's native types directly. Mastering sizes, signedness, and conversions is essential for correct and portable code. 

#include <stdio.h>
#include <stdint.h>   /* fixed-width integers */

int main(void) {
    char c = 'A';                 /* at least 8 bits */
    short s = 1000;               /* small integer */
    int i = 42;                   /* natural integer */
    long l = 123456789L;          /* long integer */
    long long ll = 9LL;           /* very long integer */

    unsigned int u = 4000000000U; /* wraps at UINT_MAX */
    uint32_t exact = 0xDEADBEEF;  /* exactly 32 bits */

    float f = 3.14f;
    double d = 3.141592653589793;
    _Bool flag = 1;               /* C99 boolean */

    printf("int size = %zu bytes\n", sizeof(int));
    return 0;
}

Integer literals

  • 42 is an int.
  • 42L is a long.
  • 42U is unsigned.
  • 0x2A is hexadecimal.
  • 052 is octal (avoid leading zeros).
  • 0b101010 is binary (C23).

Constants

const creates read-only variables. Prefer it over #define when you need a typed value or a pointer to constant data.

const int max_users = 100;
const char *msg = "read-only string";

Operators

int a = 10, b = 3;
int sum = a + b;          /* arithmetic */
int mod = a % b;          /* remainder */
int bit = a & b;          /* bitwise AND */
int shift = a << 1;       /* left shift */
_Bool eq = (a == b);      /* relational */
_Bool both = a && b;      /* logical */
int big = (a > b) ? a : b; /* ternary */
size_t sz = sizeof(a);    /* bytes used */

/* Compound assignment */
a += 5;   /* a = a + 5 */

Promotion, conversion, and undefined behavior

  • Smaller integer types are promoted to int before most operations.
  • Assigning a wider type to a narrower one may truncate silently.
  • Signed integer overflow is undefined behavior. Use unsigned types or check bounds.
  • Never divide by zero or shift by the width of the type.
unsigned int x = 4294967295U;
x = x + 1;    /* wraps to 0: defined for unsigned */

int y = 2147483647;
y = y + 1;    /* signed overflow: undefined behavior */

Chapter 4

Control Flow

Control-flow statements decide which code runs and how many times. C keeps them minimal but powerful. 

#include <stdio.h>

int main(void) {
    int score = 85;

    if (score >= 90) {
        printf("A\n");
    } else if (score >= 80) {
        printf("B\n");
    } else if (score >= 70) {
        printf("C\n");
    } else {
        printf("F\n");
    }

    int option = 2;
    switch (option) {
        case 1: printf("One\n"); break;
        case 2: printf("Two\n"); break;
        case 3: printf("Three\n"); break;
        default: printf("Other\n"); break;
    }

    return 0;
}

Loops

for (int i = 0; i < 10; i++) {
    printf("%d\n", i);
}

int n = 5;
while (n > 0) {
    printf("%d\n", n--);
}

int m = 0;
do {
    printf("at least once\n");
} while (m > 0);

Jump statements

  • break exits the nearest loop or switch.
  • continue skips to the next loop iteration.
  • goto jumps to a label. Use sparingly; common valid uses are centralized cleanup and breaking out of nested loops.
  • return exits a function and gives a value.

Real-world pattern: early exit

Return early to keep the happy path unindented and reduce nesting. This is often called "guard clauses."

double safe_divide(double a, double b) {
    if (b == 0.0) {
        return 0.0 / 0.0;   /* NaN */
    }
    return a / b;
}

Chapter 5

Functions & Recursion

Functions split programs into reusable pieces. C passes all arguments by value, so a function receives a copy unless you explicitly pass a pointer. 

#include <stdio.h>

/* declaration / prototype */
int add(int a, int b);

int main(void) {
    int result = add(3, 4);
    printf("3 + 4 = %d\n", result);
    return 0;
}

/* definition */
int add(int a, int b) {
    return a + b;
}

Scope and linkage

  • Block scope: variables live inside {}.
  • File scope: variables declared outside functions.
  • Internal linkage: visible only in one translation unit (use static).
  • External linkage: visible across files (default for globals).

Storage classes

  • auto: local, automatic lifetime. Implicit today.
  • static: persists for the whole program.
  • extern: refers to a definition elsewhere.
  • register: hint to keep in a register; modern compilers ignore it.

Recursion

#include <stdio.h>

unsigned long factorial(unsigned int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}

unsigned long fib(unsigned int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}

int main(void) {
    printf("5! = %lu\n", factorial(5));  /* 120 */
    printf("fib(10) = %lu\n", fib(10));  /* 55 */
    return 0;
}

Tail recursion

A tail-recursive call is the very last action in a function. Optimizing compilers can turn it into a loop, preventing stack overflow. The factorial version above is not tail-recursive because it multiplies after the call.

unsigned long factorial_tail(unsigned int n, unsigned long acc) {
    if (n <= 1) return acc;
    return factorial_tail(n - 1, n * acc);
}

unsigned long factorial(unsigned int n) {
    return factorial_tail(n, 1);
}

Chapter 6

Pointers & Arrays (Deep)

Pointers are C's superpower and its biggest source of bugs. An array is closely related to a pointer to its first element, but they are not identical. 

#include <stdio.h>

int main(void) {
    int x = 42;
    int *p = &x;     /* p holds the address of x */

    printf("x = %d\n", x);
    printf("*p = %d\n", *p);

    *p = 100;        /* dereference: write through p */
    printf("x = %d\n", x);

    return 0;
}

Pointer arithmetic

Adding one to a pointer moves by the size of the pointed-to type, not by one byte. This makes array traversal efficient and type-safe.

int nums[] = {10, 20, 30};
int *p = nums;
printf("%d\n", *(p + 1));  /* 20 */

Array decay

In most expressions, an array name decays to a pointer to its first element. sizeof(array) and &array are the main exceptions.

int a[5];
printf("%zu\n", sizeof(a));       /* 20 on 32-bit int */
void f(int *p); f(a);            /* decays */

Multi-dimensional arrays

int board[3][3] = {
    {1, 0, 0},
    {0, 1, 0},
    {0, 0, 1}
};

void print_board(int rows, int cols, int b[rows][cols]) {
    for (int r = 0; r < rows; r++) {
        for (int c = 0; c < cols; c++) {
            printf("%d ", b[r][c]);
        }
        printf("\n");
    }
}

Pointer to pointer

void swap_int_ptrs(int **a, int **b) {
    int *tmp = *a;
    *a = *b;
    *b = tmp;
}

int x = 1, y = 2;
int *px = &x, *py = &y;
swap_int_ptrs(&px, &py);

Dynamic arrays

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    size_t n = 5;
    int *arr = malloc(n * sizeof(int));
    if (!arr) {
        perror("malloc");
        return 1;
    }
    for (size_t i = 0; i < n; i++) arr[i] = (int)(i * 10);
    free(arr);   /* always free heap memory */
    return 0;
}

Common pointer pitfalls

  • Dangling pointers: pointing to freed or stack-local memory.
  • Buffer overflows: writing past the end of an array.
  • NULL dereference: using a pointer that was never initialized or was freed.
  • Memory leaks: losing the last pointer to allocated memory.

Chapter 7

Strings & Character Handling

C strings are null-terminated byte arrays. There is no built-in string type, so you must track length and buffer size yourself. 

#include <stdio.h>
#include <string.h>

int main(void) {
    char msg[] = "Hello";          /* mutable copy, 6 bytes including '\0' */
    const char *lit = "World";     /* pointer to string literal */

    printf("%zu\n", strlen(msg));  /* 5 */
    strcat(msg, "!");              /* only safe if buffer is big enough */
    printf("%s\n", msg);
    return 0;
}

Common string.h functions

  • strlen — length without \0.
  • strcpy / strncpy — copy strings.
  • strcat / strncat — concatenate.
  • strcmp / strncmp — compare.
  • strchr / strstr — search.

Safe string handling

Modern C code often uses bounds-checked alternatives or manually tracks buffer sizes. strncpy does not guarantee null-termination, so check after copying.

#include <stdio.h>
#include <string.h>

int main(void) {
    char src[] = "Copy me";
    char dst[20];

    strncpy(dst, src, sizeof(dst) - 1);
    dst[sizeof(dst) - 1] = '\0';   /* force termination */

    if (strcmp(src, dst) == 0) {
        printf("Match\n");
    }
    return 0;
}

Character classification with ctype.h

#include <ctype.h>
#include <stdio.h>

int main(void) {
    char c = 'a';
    printf("isalpha: %d, isdigit: %d, toupper: %c\n",
           isalpha(c), isdigit(c), (char)toupper(c));
    return 0;
}

Parsing simple input

#include <stdio.h>

int main(void) {
    char name[64];
    int age;
    printf("Enter name and age: ");
    if (scanf("%63s %d", name, &age) == 2) {
        printf("%s is %d years old\n", name, age);
    }
    return 0;
}

Chapter 8

Structs, Unions, Enums, Bit-fields

These constructs let you model real-world data and pack memory tightly. They are the foundation of data structures and hardware interfaces. 

#include <stdio.h>

struct Point {
    int x;
    int y;
};

struct Rectangle {
    struct Point top_left;
    struct Point bottom_right;
};

int main(void) {
    struct Point p = {10, 20};
    struct Rectangle r = {{0, 0}, {100, 200}};

    printf("Point: (%d, %d)\n", p.x, p.y);
    printf("Rectangle width: %d\n", r.bottom_right.x - r.top_left.x);
    return 0;
}

Unions

A union holds one member at a time in the same memory. It is useful for type punning, tagged variants, and memory overlays.

union Packet {
    uint32_t raw;
    struct {
        uint8_t a, b, c, d;
    } bytes;
};

Enums

Enums give names to integer constants, making state machines and option sets readable.

enum Color { RED, GREEN, BLUE };
enum Status { OK = 0, ERROR = -1, PENDING = 1 };

Bit-fields

#include <stdio.h>

struct Flags {
    unsigned int is_active : 1;
    unsigned int priority  : 3;  /* 0..7 */
    unsigned int category  : 4;  /* 0..15 */
};

int main(void) {
    struct Flags f = {1, 5, 9};
    printf("size = %zu bytes\n", sizeof(f));
    return 0;
}

Padding and alignment

Compilers insert padding so members align to natural boundaries. Reordering members can shrink a struct. You can pack with #pragma pack, but that may slow access.

struct Padded {
    char a;      /* 1 byte + 3 padding */
    int  b;      /* 4 bytes */
    char c;      /* 1 byte + 3 padding */
};  /* often 12 bytes */

struct Compact {
    int  b;
    char a;
    char c;
};  /* often 8 bytes */

Chapter 9

Dynamic Memory & Memory Layout

C gives you direct control over memory. With that power comes responsibility: every malloc needs a matching free.

Stack vs heap

  • Stack: automatic variables, function frames, fast but limited. Freed when the function returns.
  • Heap: manually managed, large, survives function calls. Use malloc / free.
  • Data segment: global and static variables.
  • Text segment: program code, usually read-only.
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    size_t n = 100;

    int *arr1 = malloc(n * sizeof(int));
    if (!arr1) { perror("malloc"); return 1; }

    int *arr2 = calloc(n, sizeof(int));   /* zeroed */
    if (!arr2) { perror("calloc"); free(arr1); return 1; }

    /* grow arr2 */
    int *tmp = realloc(arr2, 2 * n * sizeof(int));
    if (tmp) arr2 = tmp;

    free(arr1);
    free(arr2);
    return 0;
}

Common heap bugs

  • Memory leak: losing the pointer before freeing.
  • Use-after-free: reading or writing freed memory.
  • Double-free: calling free twice on the same pointer.
  • Invalid free: freeing memory not from malloc.

Safe pattern

void *p = malloc(size);
if (!p) { /* handle error */ }
/* use p */
free(p);
p = NULL;   /* avoid dangling */

Detecting leaks with Valgrind

# Compile with debug symbols
gcc -std=c11 -g -O0 leak.c -o leak

# Run under valgrind
valgrind --leak-check=full --show-leak-kinds=all ./leak

Aligned allocation

#include <stdlib.h>
#include <stdio.h>

int main(void) {
    void *p = aligned_alloc(64, 1024);  /* 64-byte aligned */
    if (!p) { perror("aligned_alloc"); return 1; }
    printf("address %p is aligned\n", p);
    free(p);
    return 0;
}

Chapter 10

Function Pointers, Callbacks & qsort

Function pointers let you pass behavior as data. They enable callbacks, plugin architectures, and table-driven dispatch. 

#include <stdio.h>

int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }

int main(void) {
    int (*op)(int, int) = add;
    printf("%d\n", op(5, 3));  /* 8 */

    op = sub;
    printf("%d\n", op(5, 3));  /* 2 */
    return 0;
}

Callback pattern

#include <stdio.h>

void for_each(int *arr, size_t n, void (*fn)(int)) {
    for (size_t i = 0; i < n; i++) fn(arr[i]);
}

void print_int(int x) { printf("%d\n", x); }

int main(void) {
    int nums[] = {1, 2, 3, 4};
    for_each(nums, 4, print_int);
    return 0;
}

Using qsort and bsearch

#include <stdio.h>
#include <stdlib.h>

int cmp_int(const void *a, const void *b) {
    int x = *(const int *)a;
    int y = *(const int *)b;
    return (x > y) - (x < y);
}

int main(void) {
    int arr[] = {3, 1, 4, 1, 5, 9, 2, 6};
    size_t n = sizeof(arr) / sizeof(arr[0]);

    qsort(arr, n, sizeof(int), cmp_int);

    int key = 5;
    int *found = bsearch(&key, arr, n, sizeof(int), cmp_int);
    if (found) printf("Found %d\n", *found);
    return 0;
}

Generic-ish code with void*

void swap(void *a, void *b, size_t size) {
    unsigned char *pa = a, *pb = b;
    for (size_t i = 0; i < size; i++) {
        unsigned char tmp = pa[i];
        pa[i] = pb[i];
        pb[i] = tmp;
    }
}

Chapter 11

File I/O & System Calls

The C standard library provides portable file functions. POSIX system calls sit underneath and offer finer control on Unix-like systems. 

#include <stdio.h>

int main(void) {
    FILE *fp = fopen("data.txt", "w");
    if (!fp) { perror("fopen"); return 1; }

    fprintf(fp, "count: %d\n", 42);
    fclose(fp);

    fp = fopen("data.txt", "r");
    if (!fp) { perror("fopen"); return 1; }

    char line[128];
    while (fgets(line, sizeof(line), fp)) {
        printf("%s", line);
    }
    fclose(fp);
    return 0;
}

Common fopen modes

  • "r" read text.
  • "w" write text, truncate.
  • "a" append text.
  • "rb" / "wb" binary.
  • "r+" / "w+" read and write.

Binary I/O

int data[10];
FILE *fp = fopen("out.bin", "wb");
fwrite(data, sizeof(int), 10, fp);
fclose(fp);

Positioning and error handling

#include <stdio.h>
#include <errno.h>

int main(void) {
    FILE *fp = fopen("data.txt", "r");
    if (!fp) {
        perror("data.txt");
        return 1;
    }

    fseek(fp, 0, SEEK_END);
    long size = ftell(fp);
    rewind(fp);

    printf("size = %ld\n", size);
    fclose(fp);
    return 0;
}

POSIX system calls intro

#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main(void) {
    int fd = open("data.txt", O_RDONLY);
    if (fd < 0) { perror("open"); return 1; }

    char buf[128];
    ssize_t n = read(fd, buf, sizeof(buf) - 1);
    if (n > 0) {
        buf[n] = '\0';
        printf("%s", buf);
    }

    lseek(fd, 0, SEEK_SET);
    close(fd);
    return 0;
}

Chapter 12

Modular Design, Headers, Build Systems

Real C projects split code into many files. Headers declare interfaces, source files implement them, and build systems tie everything together. 

/* math_utils.h */
#ifndef MATH_UTILS_H
#define MATH_UTILS_H

int add(int a, int b);
int square(int x);

#endif
/* math_utils.c */
#include "math_utils.h"

int add(int a, int b) { return a + b; }
int square(int x) { return x * x; }
/* main.c */
#include <stdio.h>
#include "math_utils.h"

int main(void) {
    printf("%d\n", add(2, 3));
    return 0;
}

A simple Makefile

CC = gcc
CFLAGS = -std=c11 -Wall -Wextra -O2

app: main.o math_utils.o
	$(CC) $(CFLAGS) -o app main.o math_utils.o

main.o: main.c math_utils.h
	$(CC) $(CFLAGS) -c main.c

math_utils.o: math_utils.c math_utils.h
	$(CC) $(CFLAGS) -c math_utils.c

clean:
	rm -f *.o app

.PHONY: clean

Static libraries

# Create archive
ar rcs libmath.a math_utils.o

# Link against it
gcc main.c -o app -L. -lmath

Dynamic libraries

# Position-independent code
gcc -fPIC -c math_utils.c

# Shared object (Linux)
gcc -shared -o libmath.so math_utils.o

# Link
gcc main.c -o app -L. -lmath

Chapter 13

Debugging & Profiling

Modern C debugging is a mix of classic tools and compiler-powered sanitizers. Compile with debug symbols and let the tools do the heavy lifting. 

# Compile with debug symbols, no optimization
gcc -std=c11 -g -O0 app.c -o app

# Start gdb
gdb ./app

# Common gdb commands
(gdb) break main        # stop at main
(gdb) run               # start execution
(gdb) next              # step over
(gdb) step              # step into
(gdb) print x           # inspect variable
(gdb) continue          # resume
(gdb) quit              # exit

Valgrind

Valgrind catches memory leaks, invalid reads/writes, and use of uninitialized memory on Linux.

valgrind --leak-check=full ./app
valgrind --tool=memcheck ./app

AddressSanitizer

AddressSanitizer is built into GCC and Clang. It finds heap and stack buffer overflows with lower overhead than Valgrind.

gcc -std=c11 -g -fsanitize=address app.c -o app
./app

Chapter 14

Advanced C

Once the fundamentals are solid, you can explore low-level bit manipulation, compiler intrinsics, custom allocators, and the sharp edges of undefined behavior.

Bitwise operations in depth

#include <stdint.h>
#include <stdio.h>

#define FLAG_A (1u << 0)
#define FLAG_B (1u << 1)
#define FLAG_C (1u << 2)

int main(void) {
    uint32_t flags = 0;
    flags |= FLAG_A;        /* set */
    flags |= FLAG_B;
    flags &= ~FLAG_B;       /* clear */
    _Bool a_on = flags & FLAG_A;
    flags ^= FLAG_C;        /* toggle */

    printf("flags = 0x%X, A = %d\n", flags, a_on);
    return 0;
}

Inline assembly

/* GCC x86_64 inline assembly example */
static inline uint64_t rdtsc(void) {
    uint32_t lo, hi;
    __asm__ __volatile__ ("rdtsc" : "=a"(lo), "=d"(hi));
    return ((uint64_t)hi << 32) | lo;
}

Arena allocator concept

#include <stdlib.h>
#include <stdint.h>

typedef struct {
    uint8_t *base;
    size_t used;
    size_t cap;
} Arena;

void *arena_alloc(Arena *a, size_t n) {
    if (a->used + n > a->cap) return NULL;
    void *p = a->base + a->used;
    a->used += n;
    return p;
}

void arena_free_all(Arena *a) { a->used = 0; }

Special qualifiers

  • volatile: tells the compiler the value may change outside the current thread, e.g. hardware registers.
  • restrict: promises that a pointer is the only way to access its target, enabling optimizations.
  • _Atomic (C11): thread-safe atomic operations.

Undefined behavior

Signed overflow, dereferencing NULL, accessing out-of-bounds memory, and violating sequence points are all undefined. The compiler is allowed to do anything, so never rely on "what the CPU usually does."

Project A: Memory-Mapped Key–Value Store

1. What is this project?

Build a tiny persistent key–value store. Strings are keys and strings are values. The store loads from a file on startup and saves on demand.

2. What it covers?

  • Hash tables and collision handling.
  • Struct design and serialization.
  • File I/O and persistence formats.
  • Optional mmap for fast loading.

3. How it is done?

#define TABLE_SIZE 1024

typedef struct Entry {
    char key[64];
    char value[256];
    struct Entry *next;   /* separate chaining */
} Entry;

typedef struct {
    Entry *buckets[TABLE_SIZE];
} KVStore;

unsigned int hash(const char *key) {
    unsigned int h = 5381;
    int c;
    while ((c = *key++)) h = ((h << 5) + h) + c;
    return h % TABLE_SIZE;
}

4. What did we learn?

  • Persistent data needs a stable on-disk format.
  • Hashing converts variable-length keys into array indices.
  • Text serialization is simple but binary formats are faster.

5. How can I enhance?

  • Use mmap to map the file directly into memory.
  • Add a write-ahead log for crash recovery.
  • Implement deletion and automatic rehashing.

Project B: Mini Shell

1. What is this project?

Implement a command-line shell that reads user input, parses it into commands and arguments, and executes programs.

2. What it covers?

  • String tokenization.
  • Process creation with fork and exec.
  • Built-in commands.
  • Pipes and I/O redirection.

3. How it is done?

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    char line[256];
    while (1) {
        printf("minish> ");
        if (!fgets(line, sizeof(line), stdin)) break;
        line[strcspn(line, "\n")] = '\0';

        if (strcmp(line, "exit") == 0) break;
        if (strncmp(line, "cd ", 3) == 0) {
            chdir(line + 3);
            continue;
        }

        pid_t pid = fork();
        if (pid == 0) {
            char *argv[] = { line, NULL };
            execvp(argv[0], argv);
            perror("execvp");
            exit(1);
        }
        waitpid(pid, NULL, 0);
    }
    return 0;
}

4. What did we learn?

  • Every external command runs in a new process.
  • execvp replaces the child process image.
  • dup2 redirects file descriptors for pipes and redirection.

5. How can I enhance?

  • Parse quoted arguments and environment variables.
  • Add pipelines like ls | wc -l.
  • Implement job control with SIGTSTP.

Project C: Custom Memory Allocator

1. What is this project?

Write your own malloc/free replacement using a free-list allocator and a bump allocator for fast temporary allocations.

2. What it covers?

  • Pointer arithmetic and alignment.
  • Free-list bookkeeping with headers.
  • Splitting and coalescing free blocks.
  • Benchmarking against the system allocator.

typedef struct Block {

static Block *free_list = NULL;

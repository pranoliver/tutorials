Go Language: Fast, Reliable Systems Programming

Chapter 1

Introduction + Installation

Go is a statically typed, compiled language designed at Google for building fast, reliable, and efficient software at scale. Its minimalist syntax, powerful concurrency model, and excellent tooling make it ideal for cloud services, command-line tools, and distributed systems.

Why learn Go?

  • Cloud native: Docker, Kubernetes, Terraform, and many CNCF projects are written in Go.
  • Fast compilation: Go builds large codebases in seconds.
  • Simple concurrency: goroutines and channels make parallel code readable.
  • Single static binary: deploy one file with no runtime dependencies.
  • Great tooling: built-in formatter, test runner, race detector, and module system.

Before you start

  • A text editor and a terminal. New to the command line? Try the Linux tutorial.
  • Optional: Git basics for saving projects.
  • No prior Go experience required.

Chapter 2

Packages, Modules & Workspace

Go programs are organized into packages, and collections of packages form modules. Modules let you version dependencies and build reproducibly anywhere.

Create a new module

mkdir greet
cd greet
go mod init example.com/greet

This produces a go.mod file that records the module path and the Go version. Add the source file below and run it with go run .. 

// greet.go
package main

import (
    "fmt"

    "example.com/greet/greeting"
)

func main() {
    fmt.Println(greeting.Hello("Ada"))
}
// greeting/greeting.go
package greeting

import "fmt"

// Hello returns a friendly greeting.
func Hello(name string) string {
    return fmt.Sprintf("Hello, %s!", name)
}

Package rules

  • Every file starts with package name.
  • Exported names begin with an uppercase letter.
  • Unexported names stay inside the package.
  • The main package builds an executable.

Useful commands

go get example.com/pkg         # add dependency
go mod tidy                    # clean go.mod / go.sum
go list -m all                 # list modules
go mod download                # fetch dependencies

Workspaces

A workspace lets you work on multiple modules at once without publishing changes. 

go work init ./greet ./greeting
cat go.work

Chapter 3

Variables, Types & Operators

Go has a small, orthogonal type system. Variables are declared with var, :=, or const. Types are explicit but inference keeps code short. 

package main

import "fmt"

func main() {
    var name string = "Ada"   // explicit
    age := 30                 // inferred int
    var pi = 3.14159          // inferred float64

    const maxRetries = 3      // compile-time constant

    var zeroValue int         // defaults to 0
    var empty string          // defaults to ""

    fmt.Printf("%s is %d, pi=%.2f\n", name, age, pi)
    fmt.Println(zeroValue, empty, maxRetries)
}

Basic types

  • bool
  • string
  • int, int8, int16, int32, int64
  • uint, uintptr, plus sized variants
  • float32, float64
  • complex64, complex128
  • byte (alias for uint8), rune (alias for int32)

Type conversions

Go does not implicitly convert between numeric types. You must request each conversion explicitly.

var i int = 42
var f float64 = float64(i)
var u uint = uint(f)
_ = u

Composite types

// Array (fixed length)
var nums [3]int = [3]int{1, 2, 3}

// Slice (dynamic view)
fruits := []string{"apple", "banana"}
fruits = append(fruits, "cherry")

// Map
scores := map[string]int{"Ada": 95, "Bob": 87}

// Struct
type Person struct {
    Name string
    Age  int
}
p := Person{Name: "Ada", Age: 30}

Operators

a, b := 10, 3
sum := a + b
mod := a % b
bit := a & b
shift := a << 1

// No ternary operator; use if/else
max := a
if b > a {
    max = b
}

Chapter 4

Control Flow

Go keeps control flow simple: if, for, switch, and defer. There is no while or do-while; a bare for loop handles those cases. 

package main

import "fmt"

func main() {
    score := 85

    if score >= 90 {
        fmt.Println("A")
    } else if score >= 80 {
        fmt.Println("B")
    } else {
        fmt.Println("C or lower")
    }

    // if with a short statement
    if v := score / 10; v == 8 {
        fmt.Println("Decile 8")
    }

    // switch
    switch score / 10 {
    case 10:
        fmt.Println("Perfect")
    case 9:
        fmt.Println("Excellent")
    case 8:
        fmt.Println("Good")
    default:
        fmt.Println("Keep practicing")
    }
}

The only loop

// classic for
for i := 0; i < 10; i++ {
    fmt.Println(i)
}

// while-style
n := 5
for n > 0 {
    fmt.Println(n)
    n--
}

// infinite
for {
    break
}

// range over slice
for i, v := range []int{1, 2, 3} {
    fmt.Println(i, v)
}

defer

A deferred function runs when the surrounding function returns, in last-in-first-out order. It is perfect for cleanup.

f, err := os.Open("file.txt")
if err != nil {
    log.Fatal(err)
}
defer f.Close()
// read from f...

Real-world pattern: guard clause

Return early on errors so the happy path stays at the left margin.

func safeDivide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, errors.New("cannot divide by zero")
    }
    return a / b, nil
}

Chapter 5

Functions

Functions are first-class values in Go. They can return multiple values, accept variadic arguments, and be passed around like any other value. 

package main

import (
    "errors"
    "fmt"
)

// Multiple return values
func divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, errors.New("division by zero")
    }
    return a / b, nil
}

// Named return values
func rectangle(w, h float64) (area, perimeter float64) {
    area = w * h
    perimeter = 2 * (w + h)
    return // naked return
}

// Variadic
func sum(nums ...int) int {
    total := 0
    for _, n := range nums {
        total += n
    }
    return total
}

func main() {
    result, err := divide(10, 2)
    if err != nil {
        fmt.Println("error:", err)
        return
    }
    fmt.Println(result, rectangle(4, 5), sum(1, 2, 3))
}

First-class functions

func apply(a, b int, op func(int, int) int) int {
    return op(a, b)
}

func main() {
    add := func(x, y int) int { return x + y }
    fmt.Println(apply(2, 3, add))
}

Closures

func counter() func() int {
    count := 0
    return func() int {
        count++
        return count
    }
}

func main() {
    c := counter()
    fmt.Println(c(), c(), c()) // 1 2 3
}

Chapter 6

Structs, Methods & Embedding

Structs group fields into a single type. Methods attach behavior to a type, and embedding composes types without classical inheritance. 

package main

import (
    "fmt"
    "math"
)

type Point struct {
    X, Y float64
}

func (p Point) Distance(q Point) float64 {
    dx := p.X - q.X
    dy := p.Y - q.Y
    return math.Sqrt(dx*dx + dy*dy)
}

func (p *Point) Move(dx, dy float64) {
    p.X += dx
    p.Y += dy
}

type Circle struct {
    Center Point
    Radius float64
}

func main() {
    a := Point{0, 0}
    b := Point{3, 4}
    fmt.Println(a.Distance(b))

    c := Circle{Center: a, Radius: 5}
    fmt.Println(c.Center.X)
}

Pointer vs value receivers

  • Value receiver: method gets a copy; cannot modify the original.
  • Pointer receiver: method can modify the original and avoids copying large structs.
  • Be consistent for a given type.

Embedding

Embedding promotes the embedded type's fields and methods to the outer struct. It is Go's composition pattern.

type Employee struct {
    Name string
}

type Manager struct {
    Employee    // embedded
    Reports []string
}

m := Manager{}
m.Name = "Ada" // promoted field

Tags and JSON

type User struct {
    ID        int       `json:"id"`
    Email     string    `json:"email"`
    CreatedAt time.Time `json:"created_at"`
}

Chapter 7

Interfaces

Interfaces in Go are satisfied implicitly. A type implements an interface by implementing its methods, with no explicit declaration. This leads to flexible, decoupled designs. 

package main

import "fmt"

type Speaker interface {
    Speak() string
}

type Dog struct{}

func (d Dog) Speak() string { return "Woof!" }

type Cat struct{}

func (c Cat) Speak() string { return "Meow!" }

func Greet(s Speaker) {
    fmt.Println(s.Speak())
}

func main() {
    Greet(Dog{})
    Greet(Cat{})
}

Common interfaces

  • error: the built-in error interface.
  • fmt.Stringer: anything with String() string.
  • io.Reader / io.Writer: streams.
  • context.Context: cancellation and request metadata.

Empty interface

interface{} (or any since Go 1.18) can hold any value. Use it sparingly; prefer concrete types or type parameters.

var x any = 42
v, ok := x.(int) // type assertion
if ok {
    fmt.Println(v + 1)
}

Type switches

func describe(v any) {
    switch t := v.(type) {
    case int:
        fmt.Printf("integer %d\n", t)
    case string:
        fmt.Printf("string %q\n", t)
    default:
        fmt.Printf("unknown %T\n", t)
    }
}

Chapter 8

Goroutines, Channels & Select

Concurrency is the heart of Go. Goroutines are lightweight threads managed by the runtime, and channels let them communicate safely. The mantra is: do not communicate by sharing memory; share memory by communicating. 

package main

import (
    "fmt"
    "time"
)

func say(msg string) {
    for i := 0; i < 3; i++ {
        fmt.Println(msg)
        time.Sleep(100 * time.Millisecond)
    }
}

func main() {
    go say("async")   // new goroutine
    say("sync")       // main goroutine
}

Channels

func main() {
    ch := make(chan string) // unbuffered

    go func() {
        ch <- "hello from a goroutine"
    }()

    msg := <-ch
    fmt.Println(msg)
}

Buffered channels

ch := make(chan int, 3)
ch <- 1
ch <- 2
fmt.Println(<-ch)
fmt.Println(<-ch)

Channel directions

func producer(out chan<- int) {
    out <- 42
}

func consumer(in <-chan int) {
    fmt.Println(<-in)
}

Select

func main() {
    ch1 := make(chan string)
    ch2 := make(chan string)

    go func() { ch1 <- "first" }()
    go func() { ch2 <- "second" }()

    for i := 0; i < 2; i++ {
        select {
        case m := <-ch1:
            fmt.Println("ch1:", m)
        case m := <-ch2:
            fmt.Println("ch2:", m)
        case <-time.After(1 * time.Second):
            fmt.Println("timeout")
        }
    }
}

Closing channels

Only the sender should close a channel. Receivers can detect closure with v, ok := <-ch; ok is false after close. Ranging over a channel stops when it closes.

Chapter 9

Sync Package & Patterns

Channels are not always the right tool. The sync package provides mutexes, wait groups, and once semantics for shared-state concurrency. 

package main

import (
    "fmt"
    "sync"
)

func main() {
    var wg sync.WaitGroup
    var mu sync.Mutex
    counter := 0

    for i := 0; i < 100; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            mu.Lock()
            counter++
            mu.Unlock()
        }()
    }

    wg.Wait()
    fmt.Println(counter)
}

Sync primitives

  • sync.Mutex: exclusive lock.
  • sync.RWMutex: many readers, one writer.
  • sync.WaitGroup: wait for goroutines to finish.
  • sync.Once: run initialization exactly once.
  • sync.Map: concurrent map (use sparingly).

Atomic counters

var count int64
atomic.AddInt64(&count, 1)
fmt.Println(atomic.LoadInt64(&count))

Pipeline pattern

func gen(nums ...int) <-chan int {
    out := make(chan int)
    go func() {
        for _, n := range nums {
            out <- n
        }
        close(out)
    }()
    return out
}

func sq(in <-chan int) <-chan int {
    out := make(chan int)
    go func() {
        for n := range in {
            out <- n * n
        }
        close(out)
    }()
    return out
}

func main() {
    for n := range sq(gen(2, 3, 4)) {
        fmt.Println(n)
    }
}

Chapter 10

Error Handling

Go treats errors as values. Functions return an error alongside their primary result, and callers check it immediately. This keeps error paths explicit and composable. 

package main

import (
    "errors"
    "fmt"
)

var ErrNotFound = errors.New("not found")

type ValidationError struct {
    Field string
}

func (e ValidationError) Error() string {
    return fmt.Sprintf("invalid field: %s", e.Field)
}

func find(id int) (string, error) {
    if id <= 0 {
        return "", ValidationError{Field: "id"}
    }
    if id != 42 {
        return "", ErrNotFound
    }
    return "answer", nil
}

func main() {
    _, err := find(0)
    if errors.Is(err, ErrNotFound) {
        fmt.Println("not found")
    } else {
        fmt.Println(err)
    }
}

Error wrapping

if err != nil {
    return fmt.Errorf("read config: %w", err)
}

// later
if errors.Is(err, ErrNotFound) { ... }
if var e *os.PathError; errors.As(err, &e) { ... }

Panic and recover

Use panic for unrecoverable bugs, not for routine errors. recover can catch a panic inside a deferred function to prevent a crash.

func safe() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("recovered:", r)
        }
    }()
    panic("boom")
}

Chapter 11

Testing & Benchmarking

Go includes testing in the standard toolchain. Write tests in files ending with _test.go, run them with go test, and measure performance with benchmarks. 

// math.go
package math

func Add(a, b int) int {
    return a + b
}
// math_test.go
package math

import "testing"

func TestAdd(t *testing.T) {
    got := Add(2, 3)
    want := 5
    if got != want {
        t.Errorf("Add(2,3) = %d; want %d", got, want)
    }
}

func TestAddTable(t *testing.T) {
    cases := []struct {
        a, b, want int
    }{
        {1, 2, 3},
        {0, 0, 0},
        {-1, 1, 0},
    }
    for _, c := range cases {
        got := Add(c.a, c.b)
        if got != c.want {
            t.Errorf("Add(%d,%d) = %d; want %d", c.a, c.b, got, c.want)
        }
    }
}

Benchmarks

func BenchmarkAdd(b *testing.B) {
    for i := 0; i < b.N; i++ {
        Add(2, 3)
    }
}

Run with go test -bench=.

Coverage and race

go test ./...
go test -cover ./...
go test -race ./...

Example tests

func ExampleAdd() {
    fmt.Println(Add(2, 3))
    // Output: 5
}

Chapter 12

Standard Library: HTTP, JSON, SQL

Go's standard library is famously productive. You can stand up an HTTP server, marshal JSON, and query a database with only the standard packages and a driver.

net/http

package main

import (
    "fmt"
    "net/http"
)

func hello(w http.ResponseWriter, r *http.Request) {
    fmt.Fprintf(w, "Hello, %s!\n", r.URL.Path[1:])
}

func main() {
    http.HandleFunc("/", hello)
    http.ListenAndServe(":8080", nil)
}

encoding/json

package main

import (
    "encoding/json"
    "fmt"
)

type User struct {
    ID    int    `json:"id"`
    Name  string `json:"name"`
    Admin bool   `json:"admin,omitempty"`
}

func main() {
    u := User{ID: 1, Name: "Ada"}
    b, _ := json.Marshal(u)
    fmt.Println(string(b))

    var parsed User
    json.Unmarshal(b, &parsed)
}

database/sql

package main

import (
    "database/sql"
    "fmt"
    "log"

    _ "github.com/mattn/go-sqlite3"
)

func main() {
    db, err := sql.Open("sqlite3", "app.db")
    if err != nil {
        log.Fatal(err)
    }
    defer db.Close()

    rows, err := db.Query("SELECT id, name FROM users")
    if err != nil {
        log.Fatal(err)
    }
    defer rows.Close()

    for rows.Next() {
        var id int
        var name string
        rows.Scan(&id, &name)
        fmt.Println(id, name)
    }
}

SQL driver note

database/sql provides the interface; you import a concrete driver such as github.com/mattn/go-sqlite3 or github.com/lib/pq for side effects only.

Chapter 13

Context, Reflection & Advanced Topics

As programs grow, you need to propagate cancellation deadlines, inspect types at runtime, and handle signals and timeouts gracefully.

context

package main

import (
    "context"
    "fmt"
    "time"
)

func slow(ctx context.Context) error {
    select {
    case <-time.After(2 * time.Second):
        fmt.Println("finished")
        return nil
    case <-ctx.Done():
        return ctx.Err()
    }
}

func main() {
    ctx, cancel := context.WithTimeout(context.Background(), 500*time.Millisecond)
    defer cancel()

    if err := slow(ctx); err != nil {
        fmt.Println("error:", err)
    }
}

Reflection basics

package main

import (
    "fmt"
    "reflect"
)

type User struct {
    Name string `json:"name"`
}

func main() {
    t := reflect.TypeOf(User{})
    for i := 0; i < t.NumField(); i++ {
        f := t.Field(i)
        fmt.Println(f.Name, f.Tag.Get("json"))
    }
}

Generics

func Min[T constraints.Ordered](a, b T) T {
    if a < b {
        return a
    }
    return b
}

Go 1.18 introduced type parameters for writing generic algorithms.

Signals

sig := make(chan os.Signal, 1)
signal.Notify(sig, syscall.SIGINT, syscall.SIGTERM)
<-sig

Chapter 14

Deployment & FFI

Go compiles to a single static binary that is easy to deploy. It also supports cgo for calling C libraries when you need to interoperate with native code.

Cross compilation

# Build for Linux from macOS
GOOS=linux GOARCH=amd64 go build -o app-linux .

# Build for Windows
GOOS=windows GOARCH=amd64 go build -o app.exe .

# Build a smaller binary
CGO_ENABLED=0 go build -ldflags="-s -w" -o app .

Docker example

# syntax=docker/dockerfile:1
FROM golang:1.23 AS build
WORKDIR /app
COPY . .
RUN CGO_ENABLED=0 go build -o server .

FROM gcr.io/distroless/static-debian12
COPY --from=build /app/server /server
EXPOSE 8080
ENTRYPOINT ["/server"]

cgo / FFI mention

// #include <math.h>
import "C"
import "fmt"

func main() {
    fmt.Println(C.sqrt(2))
}

cgo caveats

  • cgo breaks pure-Go cross compilation.
  • C memory is not managed by Go's garbage collector.
  • Prefer pure Go packages; use cgo only when necessary.

Capstone Projects

These three projects cover the most common Go domains: web services, concurrent pipelines, and command-line tooling. Complete them in any order, then extend.

Project A: RESTful URL Shortener / Key-Value Service

1. What is this project?

Build an HTTP service that stores short key-value pairs. Clients POST a JSON payload to create a short key and GET a key to retrieve the original value. In-memory storage keeps the project self-contained.

2. What it covers?

  • net/http handlers and routing.
  • encoding/json marshaling and unmarshaling.
  • Maps protected by a mutex for concurrent access.
  • Basic REST conventions: POST to create, GET to read.

3. How it is done?

package main

import (
    "encoding/json"
    "net/http"
    "sync"
)

type Store struct {
    mu   sync.RWMutex
    data map[string]string
}

func (s *Store) Set(key, value string) {
    s.mu.Lock()
    defer s.mu.Unlock()
    s.data[key] = value
}

func (s *Store) Get(key string) (string, bool) {
    s.mu.RLock()
    defer s.mu.RUnlock()
    v, ok := s.data[key]
    return v, ok
}

type createReq struct {
    Key   string `json:"key"`
    Value string `json:"value"`
}

func main() {
    store := &Store{data: make(map[string]string)}

    http.HandleFunc("/kv", func(w http.ResponseWriter, r *http.Request) {
        switch r.Method {
        case http.MethodPost:
            var req createReq
            if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
                http.Error(w, err.Error(), http.StatusBadRequest)
                return
            }
            store.Set(req.Key, req.Value)
            w.WriteHeader(http.StatusCreated)
        default:
            http.Error(w, "method not allowed", http.StatusMethodNotAllowed)
        }
    })

    http.HandleFunc("/kv/", func(w http.ResponseWriter, r *http.Request) {
        key := r.URL.Path[len("/kv/"):]
        v, ok := store.Get(key)
        if !ok {
            http.NotFound(w, r)
            return
        }
        json.NewEncoder(w).Encode(map[string]string{"value": v})
    })

    http.ListenAndServe(":8080", nil)
}

4. What did we learn?

  • HTTP handlers are functions with a signature, not classes.
  • JSON maps naturally to Go structs with tags.
  • Shared maps need synchronization to avoid data races.

5. How can I enhance?

  • Persist data to a file or SQLite database.
  • Generate short random keys instead of user-supplied keys.
  • Add redirects from /s/{key} to the original URL.

Project B: Concurrent Worker Pool / Pipeline

1. What is this project?

Build a fixed-size worker pool that reads jobs from a channel, processes them concurrently, and sends results to another channel. This is a foundational pattern for backends, crawlers, and ETL jobs.

2. What it covers?

  • Goroutines and channels for job distribution.
  • sync.WaitGroup to wait for workers.
  • Controlled concurrency with a fixed pool size.
  • Graceful shutdown after all jobs finish.

3. How it is done?

package main

import (
    "fmt"
    "sync"
)

type Job struct {
    ID    int
    Input int
}

type Result struct {
    JobID int
    Value int
}

func worker(id int, jobs <-chan Job, results chan<- Result, wg *sync.WaitGroup) {
    defer wg.Done()
    for j := range jobs {
        fmt.Printf("worker %d processing job %d\n", id, j.ID)
        results <- Result{JobID: j.ID, Value: j.Input * j.Input}
    }
}

func main() {
    const numJobs = 20
    const numWorkers = 4

    jobs := make(chan Job, numJobs)
    results := make(chan Result, numJobs)
    var wg sync.WaitGroup

    for w := 1; w <= numWorkers; w++ {
        wg.Add(1)
        go worker(w, jobs, results, &wg)
    }

    for j := 1; j <= numJobs; j++ {
        jobs <- Job{ID: j, Input: j}
    }
    close(jobs)

    go func() {
        wg.Wait()
        close(results)
    }()

    for r := range results {
        fmt.Printf("result: job=%d value=%d\n", r.JobID, r.Value)
    }
}

4. What did we learn?

  • A worker pool limits resource usage while still running concurrently.
  • Closing the jobs channel signals workers to stop.
  • A separate goroutine can close the results channel after workers finish.

5. How can I enhance?

  • Add a context so jobs can be cancelled mid-flight.
  • Collect per-worker metrics and throughput.
  • Retry failed jobs with exponential backoff.

Project C: CLI Tool with Flags and JSON Config

1. What is this project?

Build a command-line tool that loads settings from a JSON file and accepts cobra-style flags for host, port, and verbose mode. This mirrors real Go CLIs and microservice starters.

2. What it covers?

  • flag package for parsing arguments.
  • os and encoding/json for config files.
  • Merging config defaults, file values, and CLI overrides.
  • Subcommand structure using the standard flag set.

3. How it is done?

package main

import (
    "encoding/json"
    "flag"
    "fmt"
    "os"
)

type Config struct {
    Host    string `json:"host"`
    Port    int    `json:"port"`
    Verbose bool   `json:"verbose"`
}

func loadConfig(path string) (Config, error) {
    var cfg Config
    data, err := os.ReadFile(path)
    if err != nil {
        return cfg, err
    }
    if err := json.Unmarshal(data, &cfg); err != nil {
        return cfg, err
    }
    return cfg, nil
}

func main() {
    cfg := Config{Host: "localhost", Port: 8080}

    configPath := flag.String("config", "", "path to JSON config")
    host := flag.String("host", "", "server host")
    port := flag.Int("port", 0, "server port")
    verbose := flag.Bool("verbose", false, "enable verbose logging")
    flag.Parse()

    if *configPath != "" {
        loaded, err := loadConfig(*configPath)
        if err != nil {
            fmt.Fprintln(os.Stderr, "config error:", err)
            os.Exit(1)
        }
        cfg = loaded
    }
    if *host != "" {
        cfg.Host = *host
    }
    if *port != 0 {
        cfg.Port = *port
    }
    if *verbose {
        cfg.Verbose = true
    }

    fmt.Printf("running on %s:%d (verbose=%v)\n", cfg.Host, cfg.Port, cfg.Verbose)
}

4. What did we learn?

  • Flags provide a simple CLI without external dependencies.
  • Config files make tools reusable across environments.
  • Layered overrides let CLI flags win over config files.

5. How can I enhance?

  • Replace flag with cobra and add subcommands.
  • Support environment variables via os.Getenv.
  • Validate the merged config before starting the application.

Chapter 2

Messaging Systems

Messaging systems decouple producers from consumers. A message queue delivers each message to one consumer; a stream lets many consumers read the same events, retaining them for replay.

Message queues

  • RabbitMQ: traditional broker with routing and acknowledgments.
  • AWS SQS: fully managed queue service.
  • Good for job distribution and task queues.

Stream platforms

  • Apache Kafka: distributed commit log, high throughput, replayable.
  • AWS Kinesis, Azure Event Hubs: managed streaming.
  • Good for event sourcing, metrics, and real-time analytics.

Chapter 3

Stream Processing

Stream processing reads events continuously, applies transformations or aggregations, and emits results with low latency. It is the opposite of batch processing, which waits for a bounded dataset to finish.

Stream vs batch

  • Batch: bounded input, high throughput, higher latency.
  • Stream: unbounded input, continuous processing, lower latency.
  • Micro-batch: a hybrid with small fixed intervals.

Windowing

  • Tumbling: fixed, non-overlapping windows.
  • Sliding: overlapping windows.
  • Session: windows that close after a gap of inactivity.

Chapter 4

Spark & Hadoop Basics

Apache Spark is the dominant engine for large-scale batch and stream processing. Hadoop introduced the core ideas of distributed storage (HDFS) and processing (MapReduce, YARN) that Spark builds upon.

Hadoop ecosystem

  • HDFS: distributed file system.
  • YARN: resource manager for cluster jobs.
  • MapReduce: early batch processing paradigm.

Spark abstractions

  • RDD: resilient distributed dataset, low-level.
  • DataFrame: columnar API with Catalyst optimization.
  • Dataset: typed DataFrame (Scala/Java).

Chapter 6

Choosing Cloud Technologies

Cloud choices should be driven by data volume, latency, query patterns, team expertise, and cost. Avoid picking a service because it is trendy; pick it because it fits the access pattern.

When to use what

  • Object storage: data lake landing zone, backups, archives.
  • Data warehouse: SQL analytics, BI, large aggregations.
  • Managed OLTP: applications that need transactions.
  • Stream service: real-time ingestion and event-driven apps.

Serverless options

  • AWS Lambda + S3 + Athena: event-driven ETL.
  • Google BigQuery: serverless warehouse.
  • Azure Functions + Blob + Synapse: similar serverless stack.

Chapter 7

Cluster Computing & Serverless

Cluster computing distributes work across many nodes. Managed Kubernetes, Spark clusters, and serverless functions let data engineers scale without managing hardware. See Kubernetes and Docker for fundamentals.

Cluster models

  • Long-lived clusters: always-on Spark/Kubernetes for steady workloads.
  • Job clusters: spin up for a specific job, then terminate.
  • Serverless: pay per query or per invocation.

Trade-offs

  • Clusters give control and predictable performance.
  • Serverless reduces operational overhead and scales to zero.
  • Cold starts and per-query costs can surprise at scale.

Chapter 8

Capstone: Real-Time SaaS Event Pipeline

1. What is this project?

You will build a conceptual real-time pipeline: produce simulated SaaS events to Kafka, consume and parse them, aggregate with PySpark Structured Streaming, write to a target table, and monitor lag and throughput. For a local browser-safe demo, the sink uses SQLite instead of a real cloud warehouse.

2. What it covers?

  • Produce simulated SaaS events to a Kafka topic.
  • Consume and parse events with a Kafka consumer.
  • Aggregate events with PySpark Structured Streaming.
  • Write results to a target table/cloud sink concept.
  • Monitor lag and throughput.

3. How it is done?

Install Kafka and PySpark locally, create a topic, run the producer and consumer, then add the Spark streaming aggregation. The SQLite sink is a stand-in for BigQuery or Redshift.

# producer.py: simulate SaaS events to Kafka
cat << 'EOF' > producer.py
import json, time, random
from kafka import KafkaProducer

producer = KafkaProducer(
    bootstrap_servers=['localhost:9092'],
    value_serializer=lambda v: json.dumps(v).encode('utf-8')
)

event_types = ['page_view', 'click', 'signup']
while True:
    event = {
        'event_id': f"evt_{random.randint(1, 1000000)}",
        'user_id': random.randint(1, 1000),
        'event_type': random.choice(event_types),
        'page': random.choice(['/', '/pricing', '/docs']),
        'ts': time.time()
    }
    producer.send('saas-events', event)
    time.sleep(0.5)
EOF

uv run --with kafka-python producer.py
# consumer.py: read from Kafka and parse JSON
cat << 'EOF' > consumer.py
import json
from kafka import KafkaConsumer

consumer = KafkaConsumer(
    'saas-events',
    bootstrap_servers=['localhost:9092'],
    auto_offset_reset='earliest',
    value_deserializer=lambda m: json.loads(m.decode('utf-8'))
)

for msg in consumer:
    print(msg.value)
    # In production, write parsed records to a sink.
EOF

uv run --with kafka-python consumer.py
# spark_stream.py: aggregate events with Structured Streaming
cat << 'EOF' > spark_stream.py
from pyspark.sql import SparkSession
from pyspark.sql.functions import from_json, col, window, count
from pyspark.sql.types import StructType, StringType, IntegerType, DoubleType

schema = StructType() \
    .add("event_id", StringType()) \
    .add("user_id", IntegerType()) \
    .add("event_type", StringType()) \
    .add("page", StringType()) \
    .add("ts", DoubleType())

spark = SparkSession.builder \
    .appName("SaaSStreaming") \
    .getOrCreate()

raw = spark.readStream.format("kafka") \
    .option("kafka.bootstrap.servers", "localhost:9092") \
    .option("subscribe", "saas-events") \
    .load()

parsed = raw.select(from_json(col("value").cast("string"), schema).alias("data")) \
    .select("data.*") \
    .withColumn("event_ts", col("ts").cast("timestamp"))

agg = parsed.withWatermark("event_ts", "1 minute") \
    .groupBy(window("event_ts", "1 minute"), "event_type") \
    .agg(count("*").alias("event_count"))

query = agg.writeStream.outputMode("append") \
    .format("console") \
    .option("truncate", "false") \
    .start()

query.awaitTermination()
EOF

uv run --with pyspark spark_stream.py
-- SQLite sink for local demo (stand-in for BigQuery/Redshift)
CREATE TABLE IF NOT EXISTS minute_event_counts (
    window_start TEXT,
    window_end TEXT,
    event_type TEXT,
    event_count INT,
    inserted_at TEXT DEFAULT CURRENT_TIMESTAMP
);

-- Monitoring query: check throughput
SELECT window_start, SUM(event_count) AS total
FROM minute_event_counts
GROUP BY window_start
ORDER BY window_start DESC
LIMIT 10;

4. What did we learn from this capstone project?

  • Kafka topics and partitions provide scalable, durable event streams.
  • Spark Structured Streaming bridges batch and streaming APIs.
  • Watermarks and windows handle late-arriving data.
  • Monitoring lag and throughput is essential for production streaming.

5. How can I enhance this project in the future?

  • Replace the SQLite sink with BigQuery/Redshift streaming inserts.
  • Add exactly-once semantics with idempotent writes.
  • Use Kafka Connect to ingest from databases or object storage.
  • Deploy on a managed Kubernetes cluster with Strimzi or Confluent.
  • Add auto-scaling based on consumer lag metrics.

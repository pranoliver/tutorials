C++: Modern Systems & Object-Oriented Programming

Chapter 1

Introduction + Installation

C++ is a multi-paradigm systems language that evolved from C. It adds object-oriented, generic, and functional features while keeping the ability to write low-level, high-performance code.

Why learn C++?

  • Games: Unreal Engine and many custom engines are C++.
  • Browsers: Chrome, Firefox, and Safari use C++ for rendering and JavaScript engines.
  • Databases: MySQL, MongoDB, and countless financial systems.
  • HFT and embedded: Zero-cost abstractions with deterministic performance.

Before you start

  • Familiarity with C or another programming language is helpful.
  • New to the command line? Try the Linux tutorial.
  • Track your code with Git & GitHub.

Install a C++ compiler

Windows

Install Visual Studio with the Desktop development with C++ workload, or MinGW-w64.

# MinGW-w64 via MSYS2 (inside MSYS2 terminal)
pacman -S mingw-w64-ucrt-x86_64-gcc

# Verify
g++ --version
cl.exe  # MSVC

macOS

Install Xcode Command Line Tools or the latest Clang/GCC from Homebrew.

xcode-select --install
brew install gcc

# Verify
clang++ --version

Linux

Install g++ or clang++ through your package manager.

# Debian / Ubuntu
sudo apt update
sudo apt install build-essential cmake

# Fedora
sudo dnf install gcc-c++ cmake

# Verify
g++ --version

    std::cout << "Hello, World!\n";
    return 0;
}

g++ -std=c++17 -Wall -Wextra -O2 -o hello hello.cpp

Chapter 2

C++ Basics: Beyond C

C++ keeps C's low-level control and adds safety, expressiveness, and convenience. These core ideas appear in every C++ program. 

#include <iostream>
#include <string>

namespace math {
    constexpr double pi = 3.141592653589793;
}

using IntList = int[10];   // type alias

int main() {
    int x = 42;
    int &ref = x;          // reference: alias for x
    ref = 100;

    const int max = 100;    // read-only
    auto y = x;             // int
    decltype(y) z = 0;      // int

    std::string s = "C++ is powerful";
    std::cout << s << "\n";
    std::cout << math::pi << "\n";

    return 0;
}

References vs pointers

  • A reference must be initialized and cannot be rebound.
  • References are safer syntax for aliasing.
  • Pointers can be null and can be reassigned.
  • Prefer references when null is not expected.

nullptr and constexpr

  • nullptr is the type-safe null pointer.
  • constexpr values are known at compile time.
  • const makes an object read-only at runtime.

const correctness

const int a = 5;              // a cannot change
const int *p = &a;            // data is const, pointer is not
int b = 10;
int *const q = &b;             // pointer is const, data is not
const int *const r = &a;      // both const

void print(const std::string &s);  // promise not to modify s

Chapter 3

Functions in C++

C++ functions are more flexible than C functions thanks to overloading, default arguments, references, and compile-time evaluation. 

#include <iostream>
#include <string>

// Default argument
void greet(const std::string &name, const std::string &greeting = "Hello") {
    std::cout << greeting << ", " << name << "!\n";
}

// Overloaded functions
int add(int a, int b) { return a + b; }
double add(double a, double b) { return a + b; }

// Pass by value, reference, const reference
void demo(int v, int &r, const int &cr) {
    r = v + cr;
}

// constexpr function
constexpr int square(int x) { return x * x; }

int main() {
    greet("Ada");
    std::cout << add(2, 3) << " " << add(2.5, 3.5) << "\n";
    std::cout << square(12) << "\n";   // evaluated at compile time
    return 0;
}

Passing style cheat sheet

  • T x: copy. Safe but expensive for big objects.
  • T &x: mutable reference. Caller sees changes.
  • const T &x: read-only reference. Cheap and safe.

Chapter 4

Classes & OOP

A class bundles data and behavior. Constructors create objects, destructors clean them up, and access specifiers control who can touch what. 

#include <iostream>
#include <string>

class BankAccount {
public:
    BankAccount(const std::string &owner, double balance)
        : owner_(owner), balance_(balance) {
        std::cout << "Account created for " << owner_ << "\n";
    }

    void deposit(double amount) {
        if (amount > 0) balance_ += amount;
    }

    double balance() const { return balance_; }

private:
    std::string owner_;
    double balance_;
};

int main() {
    BankAccount acc("Alice", 100.0);
    acc.deposit(50.0);
    std::cout << "Balance: " << acc.balance() << "\n";
    return 0;
}

Classes vs structs

The only difference is default access: class defaults to private, struct defaults to public. Use struct for plain data aggregates.

this and static members

this is a pointer to the current object. Static members belong to the class, not an instance.

class Widget {
public:
    static int count;
    Widget() { ++count; }
};
int Widget::count = 0;

Chapter 5

Inheritance & Polymorphism

Inheritance lets a new class reuse and extend an existing class. Polymorphism lets you treat derived objects through base pointers. 

#include <iostream>
#include <memory>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;   // pure virtual
};

class Circle : public Shape {
public:
    Circle(double r) : radius_(r) {}
    double area() const override { return 3.14159 * radius_ * radius_; }
private:
    double radius_;
};

class Rectangle : public Shape {
public:
    Rectangle(double w, double h) : width_(w), height_(h) {}
    double area() const override { return width_ * height_; }
private:
    double width_, height_;
};

int main() {
    std::unique_ptr<Shape> s1 = std::make_unique<Circle>(5.0);
    std::unique_ptr<Shape> s2 = std::make_unique<Rectangle>(4.0, 6.0);
    std::cout << s1->area() << "\n";
    std::cout << s2->area() << "\n";
    return 0;
}

Inheritance access levels

  • public inheritance: is-a relationship.
  • protected inheritance: less common.
  • private inheritance: implementation reuse, not is-a.

Virtual base classes

Multiple inheritance can create a diamond. Virtual inheritance ensures the base class is shared, not duplicated.

Slicing problem

Circle c(5.0);
Shape s = c;       // BAD: only Shape part is copied
Shape &ref = c;   // OK: reference to whole Circle
Shape *ptr = &c;  // OK: polymorphism works

Chapter 6

Operator Overloading & RAII

Operator overloading lets your types act like built-in types. RAII ties resource lifetime to object lifetime so cleanup is automatic. 

#include <iostream>

class Fraction {
public:
    Fraction(int n, int d) : num_(n), den_(d) {}

    Fraction operator+(const Fraction &other) const {
        return Fraction(num_ * other.den_ + other.num_ * den_,
                        den_ * other.den_);
    }

    bool operator==(const Fraction &other) const {
        return num_ * other.den_ == other.num_ * den_;
    }

    friend std::ostream &operator<<(std::ostream &os, const Fraction &f) {
        return os << f.num_ << "/" << f.den_;
    }

private:
    int num_, den_;
};

int main() {
    Fraction a(1, 2), b(1, 3);
    std::cout << (a + b) << "\n";
    return 0;
}

Rule of 0 / 3 / 5

  • Rule of 0: class manages no resources; compiler-generated functions are fine.
  • Rule of 3: if you write destructor, copy constructor, or copy assignment, write all three.
  • Rule of 5: add move constructor and move assignment for performance.

RAII

Acquire resources in a constructor and release them in the destructor. This turns manual resource management into automatic cleanup, even when exceptions occur.

Chapter 7

Templates & Generic Programming

Templates let you write one piece of code that works for many types. They are the engine behind the Standard Template Library. 

#include <iostream>

template <typename T>
T max_value(T a, T b) {
    return (a > b) ? a : b;
}

template <typename T, size_t N>
class Array {
public:
    T &operator[](size_t i) { return data_[i]; }
    size_t size() const { return N; }
private:
    T data_[N];
};

int main() {
    std::cout << max_value(3, 7) << "\n";
    std::cout << max_value(2.5, 1.5) << "\n";

    Array<int, 5> arr;
    arr[0] = 42;
    return 0;
}

Template facts

  • typename and class in template parameters are equivalent.
  • Explicit specialization overrides a template for one type.
  • Non-type parameters can be integers, pointers, or references.
  • SFINAE lets you disable templates based on type traits.

Chapter 8

STL Deep Dive

The Standard Template Library provides containers, iterators, and algorithms that you can combine without writing your own data structures. 

#include <iostream>
#include <vector>
#include <map>
#include <algorithm>
#include <numeric>

int main() {
    std::vector<int> v = {3, 1, 4, 1, 5, 9};
    std::sort(v.begin(), v.end());

    auto it = std::find(v.begin(), v.end(), 5);
    if (it != v.end()) std::cout << "found 5\n";

    int sum = std::accumulate(v.begin(), v.end(), 0);
    std::cout << "sum = " << sum << "\n";

    std::map<std::string, int> scores;
    scores["Alice"] = 95;
    scores["Bob"] = 87;
    for (const auto &pair : scores) {
        std::cout << pair.first << ": " << pair.second << "\n";
    }
    return 0;
}

Container quick reference

  • std::vector: dynamic array. Fast random access.
  • std::list: doubly-linked list.
  • std::deque: double-ended queue.
  • std::set / std::map: ordered tree, O(log n).
  • std::unordered_set / std::unordered_map: hash table, average O(1).

Iterator categories

  • Input: read once.
  • Output: write once.
  • Forward: read multiple times.
  • Bidirectional: move backward too.
  • Random access: arbitrary jumps.

Chapter 9

Smart Pointers & Move Semantics

Smart pointers automate memory ownership. Move semantics let expensive objects be transferred instead of copied. 

#include <iostream>
#include <memory>
#include <string>

class Resource {
public:
    Resource() { std::cout << "acquired\n"; }
    ~Resource() { std::cout << "released\n"; }
};

int main() {
    // unique ownership
    auto r1 = std::make_unique<Resource>();

    // shared ownership
    auto r2 = std::make_shared<Resource>();
    {
        auto r3 = r2;   // reference count increases
    }                  // r3 destroyed, count decreases

    // weak pointer breaks cycles
    std::weak_ptr<Resource> weak = r2;

    return 0;
}

Smart pointer summary

  • std::unique_ptr: exclusive owner.
  • std::shared_ptr: reference-counted shared owner.
  • std::weak_ptr: non-owning observer.
  • Prefer std::make_unique / std::make_shared over raw new.

Move semantics

An rvalue reference (T&&) binds to temporary values. std::move casts an lvalue to an rvalue so its resources can be stolen safely.

#include <vector>
#include <string>
#include <utility>

int main() {
    std::vector<std::string> v;
    std::string s = "a very long string";

    v.push_back(s);             // copy
    v.push_back(std::move(s));  // move; s is now valid but unspecified
    return 0;
}

Chapter 10

Lambdas & Functional Programming

Lambdas are anonymous functions. They capture local variables and integrate cleanly with the STL. 

#include <iostream>
#include <vector>
#include <algorithm>
#include <functional>

int main() {
    std::vector<int> v = {1, 2, 3, 4, 5};

    int threshold = 3;
    std::sort(v.begin(), v.end(),
              [](int a, int b) { return a > b; });

    auto count = std::count_if(v.begin(), v.end(),
                               [threshold](int x) { return x > threshold; });
    std::cout << count << " items above " << threshold << "\n";

    // Generic lambda (C++14)
    auto add = [](auto a, auto b) { return a + b; };
    std::cout << add(2, 3) << " " << add(2.5, 3.5) << "\n";

    std::function<int(int, int)> op = [](int a, int b) { return a * b; };
    return 0;
}

Capture modes

  • [] captures nothing.
  • [=] captures everything by value.
  • [&] captures everything by reference.
  • [x, &y] captures x by value and y by reference.
  • [this] captures the current object pointer.

Chapter 11

Error Handling

C++ offers exceptions for error propagation and std::optional for values that may be missing. Choose the right tool for each API. 

#include <iostream>
#include <stdexcept>
#include <optional>

class NetworkError : public std::runtime_error {
public:
    explicit NetworkError(const char *msg) : std::runtime_error(msg) {}
};

std::optional<int> parse_int(const std::string &s) {
    try {
        return std::stoi(s);
    } catch (...) {
        return std::nullopt;
    }
}

int main() {
    try {
        throw NetworkError("connection refused");
    } catch (const NetworkError &e) {
        std::cerr << "Network error: " << e.what() << "\n";
    } catch (const std::exception &e) {
        std::cerr << "Other error: " << e.what() << "\n";
    }

    if (auto val = parse_int("42")) {
        std::cout << *val << "\n";
    }
    return 0;
}

Exception safety levels

  • Basic guarantee: no leaks or corruption; object invariants hold.
  • Strong guarantee: operation either succeeds or has no effect.
  • No-throw guarantee: operation never throws.

Error codes vs exceptions

  • Use std::optional for expected missing values.
  • Use exceptions for truly exceptional failures.
  • In hot paths or across language boundaries, error codes may be better.
  • C++23 introduces std::expected for explicit error values.

Chapter 12

Concurrency

C++11 and later provide a portable threading library. Combine threads, mutexes, condition variables, and atomics to build safe parallel programs. 

#include <iostream>
#include <thread>
#include <mutex>
#include <vector>

std::mutex g_mutex;
int g_count = 0;

void worker() {
    std::lock_guard<std::mutex> lock(g_mutex);
    ++g_count;
}

int main() {
    std::vector<std::thread> threads;
    for (int i = 0; i < 10; ++i) {
        threads.emplace_back(worker);
    }
    for (auto &t : threads) t.join();
    std::cout << "count = " << g_count << "\n";
    return 0;
}

Synchronization tools

  • std::mutex with std::lock_guard for simple scopes.
  • std::unique_lock for condition variables and deferred locking.
  • std::condition_variable for producer/consumer patterns.
  • std::atomic for lock-free counters and flags.

Async tasks

#include <future>

int compute() { return 42; }

int main() {
    auto fut = std::async(std::launch::async, compute);
    std::cout << fut.get() << "\n";
    return 0;
}

Chapter 13

I/O & Filesystem

C++ streams handle formatted I/O, while C++17's filesystem library manipulates paths and directories portably. 

#include <iostream>
#include <fstream>
#include <sstream>
#include <filesystem>

namespace fs = std::filesystem;

int main() {
    // Stream I/O
    std::ofstream out("data.txt");
    out << "answer: " << 42 << "\n";
    out.close();

    std::ifstream in("data.txt");
    std::string line;
    while (std::getline(in, line)) {
        std::cout << line << "\n";
    }

    // String stream
    std::stringstream ss;
    ss << "value = " << 3.14;
    std::cout << ss.str() << "\n";

    // Filesystem
    for (const auto &entry : fs::directory_iterator(".")) {
        std::cout << entry.path() << "\n";
    }
    return 0;
}

Formatting (C++20)

#include <format>
#include <iostream>

int main() {
    std::cout << std::format("{} + {} = {}\n", 2, 3, 5);
    std::cout << std::format("{:.2f}\n", 3.14159);
    return 0;
}

CMake & Build Systems

CMake is the de facto standard for building cross-platform C++ projects. It generates native build files for Make, Ninja, Visual Studio, and Xcode.

target_include_directories(app PRIVATE include)

target_link_libraries(app PRIVATE utils)

# Release vs Debug builds
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build

Common CMake commands

  • add_executable / add_library.
  • target_include_directories.
  • target_link_libraries.
  • find_package for external dependencies.

Why CMake?

  • Single build description for many platforms.
  • Integrated with most IDEs and CI systems.
  • Handles transitive dependencies cleanly.

Chapter 15

Modern C++17/20 & Performance

Modern C++ removes boilerplate, improves type safety, and helps the compiler generate fast code. 

#include <iostream>
#include <string_view>
#include <vector>
#include <map>

// if constexpr (C++17)
template <typename T>
auto get_value(T t) {
    if constexpr (std::is_pointer_v<T>) {
        return *t;
    } else {
        return t;
    }
}

int main() {
    // Structured bindings
    std::map<std::string, int> scores = {{"Ada", 95}, {"Bob", 87}};
    for (const auto &[name, score] : scores) {
        std::cout << name << ": " << score << "\n";
    }

    // string_view avoids allocations
    std::string_view sv = "hello";
    std::cout << sv << "\n";

    return 0;
}

C++20 highlights

  • Concepts: constrain templates with named requirements.
  • Ranges: compose lazy algorithms with pipes.
  • Coroutines: asynchronous functions with co_await.
  • Modules: faster, cleaner replacement for headers.

Performance mindset

  • Zero-cost abstractions: high-level code compiles to efficient machine code.
  • Cache locality: prefer contiguous containers like std::vector.
  • Compile-time computation with constexpr reduces runtime work.
// Concepts example (C++20)
template <typename T>
concept Numeric = std::is_arithmetic_v<T>;

template <Numeric T>
T add(T a, T b) { return a + b; }

Chapter 16

Capstone Projects

These projects apply modern C++ to realistic systems. Complete one to make the ideas stick, then extend it.

Project A: High-Performance Event-Driven Server

1. What is this project?

Build a single-threaded TCP echo server that handles many clients without blocking. The goal is to understand sockets, non-blocking I/O, and event loops.

2. What it covers?

  • Berkeley sockets and poll.
  • Non-blocking file descriptors with fcntl.
  • Buffering partial reads and writes.
  • Modern C++: std::vector, smart pointers, lambdas.

3. How it is done?

// Pseudocode of the event loop
std::vector<pollfd> fds;
fds.push_back({listener_fd, POLLIN, 0});

while (true) {
    poll(fds.data(), fds.size(), -1);
    for (auto &fd : fds) {
        if (fd.revents & POLLIN) {
            if (fd.fd == listener_fd) accept_client();
            else read_and_echo(fd.fd);
        }
    }
}

4. What did we learn?

  • One thread can serve many connections when I/O is non-blocking.
  • Buffer management matters for partial network messages.
  • RAII cleans up sockets automatically on exceptions.

5. How can I enhance?

  • Use epoll or kqueue for tens of thousands of connections.
  • Add a simple chat protocol with rooms.
  • Stress test with wrk or ab.

Project B: Custom STL-like Container Library

1. What is this project?

Implement Vector and HashMap from scratch with iterators, RAII, and move semantics.

2. What it covers?

  • Manual memory management.
  • Iterator design.
  • Move constructors and move assignment.
  • Hash tables and separate chaining.

3. How it is done?

template <typename T>
class Vector {
public:
    using iterator = T*;

    Vector() = default;
    ~Vector() { delete[] data_; }

    Vector(const Vector &other);
    Vector(Vector &&other) noexcept
        : data_(other.data_), size_(other.size_), cap_(other.cap_) {
        other.data_ = nullptr;
        other.size_ = other.cap_ = 0;
    }

    void push_back(const T &value);
    iterator begin() { return data_; }
    iterator end() { return data_ + size_; }

private:
    T *data_ = nullptr;
    size_t size_ = 0;
    size_t cap_ = 0;
};

4. What did we learn?

  • STL containers look simple but hide a lot of correctness machinery.
  • Move semantics make returning large objects cheap.
  • Iterators must obey category requirements to work with algorithms.

5. How can I enhance?

  • Add emplace_back and reserve.
  • Write unit tests comparing behavior to std::vector and std::unordered_map.
  • Profile against the standard library.

Project C: Small Game Engine Component

1. What is this project?

Build an ECS-style scene manager. Entities hold polymorphic components, systems update them, and a resource manager loads assets.

2. What it covers?

  • Entity/Component design.
  • Polymorphism with smart pointers.
  • Resource manager with RAII.
  • Game loop timing.

3. How it is done?

class Component {
public:
    virtual ~Component() = default;
    virtual void update(float dt) = 0;
};

class Transform : public Component {
public:
    void update(float dt) override { /* ... */ }
};

class Entity {
public:
    std::vector<std::unique_ptr<Component>> components;
    void add(std::unique_ptr<Component> c) {
        components.push_back(std::move(c));
    }
};

4. What did we learn?

  • Polymorphism plus smart pointers simplifies object lifetime.
  • A clean game loop separates update, render, and input phases.
  • Resource managers centralize loading and unloading.

5. How can I enhance?

  • Replace virtual components with a true dense ECS using arrays of structs.
  • Add a simple rendering abstraction with SDL.
  • Serialize scene state to JSON.
